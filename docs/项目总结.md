# 随手笔记 (Hand Note) —— 项目总结

---

## 一、项目实现思路

本应用采用 **MVVM 架构** + **Room 数据库**，分层为 View（Activity/Fragment）、ViewModel（NoteViewModel）、Model（Room Entity/DAO）。核心功能包括：

- **用户系统**：注册/登录，密码暂为明文存储（已知不足），通过 userId 实现多用户数据隔离。
- **笔记 CRUD**：列表页用 RecyclerView + LiveData 观察数据自动刷新；详情页通过 noteId 区分新建（-1）和编辑（>0）模式。
- **图片附件**：系统选择器选图 → 二进制原样复制到内部目录，保留 GIF 等格式；支持查看原图、保存到相册、删除。用 Glide 加载显示。
- **录音附件**：MediaRecorder 录制 AAC/M4A 音频，支持多条录音，路径以 `||` 拼接存入数据库。MediaPlayer 实现播放控制。UI 动态构建。

路由设计：LoginActivity → MainActivity（NoteListFragment）→ NoteDetailActivity（NoteDetailFragment），通过 Intent/Bundle 传递 userId 和 noteId。

## 二、心得体会

1. 深入理解了 Room 的 Entity/DAO/Database 三要素及编译时注解机制，LiveData 作为查询返回类型可实现数据自动观察。
2. 实践了 MVVM 架构的 View 瘦身原则，掌握自定义 ViewModelProvider.Factory 传递构造参数。
3. 掌握了 MediaRecorder 完整录制流程（音源→格式→编码→输出→prepare→start），以及 MediaPlayer 的状态管理和资源释放。
4. 厘清了内部存储（filesDir）与外部存储（MediaStore）的适用场景，理解了 Android 10+ 分区存储和 FileProvider 的跨应用文件共享。
5. 学会了运行时权限请求流程，Fragment 生命周期管理（onPause 自动停止录音/播放），以及用 getViewLifecycleOwner 避免 LiveData 重复观察。
6. 工程方面：代码按功能分包（data/viewmodel/fragment/adapter），字符串用 strings.xml 统一管理，依赖用 Version Catalog（libs.versions.toml）集中声明。

## 三、课程总结

本项目覆盖了 Android 开发核心知识点：四大组件、XML 布局/RecyclerView/Material Design、Room 持久化、MVVM+LiveData 架构、多媒体处理（MediaRecorder/MediaPlayer/Glide）、存储与 FileProvider、运行时权限、多线程（ExecutorService）、Fragment 通信、Gradle 构建等。

## 四、存在的不足与错误

| 等级 | 问题 | 说明 |
|------|------|------|
| 严重 | 密码明文存储 | 无哈希/加密，数据库泄漏即暴露所有密码 |
| 严重 | fallbackToDestructiveMigration | 数据库升级时直接删除旧库，生产环境会丢数据 |
| 功能 | 录音文件定位不可靠 | 通过目录最新文件定位，并发场景可能出错 |
| 功能 | 短录音静默失败 | RuntimeException 被静默捕获，用户无提示 |
| 功能 | ExecutorService 未关闭 | LoginActivity 和 ViewModel 中线程池未 shutdown |
| 功能 | 路径分隔符不够健壮 | `\|\|` 拼接有隐患，建议用 JSON 数组或 TypeConverter |
| 体验 | 列表无附件标识 | 笔记列表不显示是否有图片/录音 |
| 体验 | 编辑页无脏数据确认 | 返回时修改内容未提示保存 |

## 五、可优化的功能

**功能扩展**：笔记搜索/筛选、云同步与备份、富文本编辑器、手写笔记、标签分类、定时提醒、语音转文字、GPS 自动填充地点、笔记分享。

**技术优化**：迁移到 Kotlin + 协程、Compose 重构 UI、密码哈希加密（SHA-256+Salt）、SQLCipher 加密数据库、DI 框架（Hilt）、WorkManager 后台同步、DiffUtil 增量列表更新、单元测试与 UI 测试补充。
